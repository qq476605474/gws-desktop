gws GUI 技术方案 — 你倾向哪种？

三种方案都能"套壳执行 gws 命令"，差别在于形态与体验。点击卡片选择，或在终端直接告诉我。

A

本地 Web 应用（推荐）

本地起一个轻量服务（Node/Bun），浏览器打开 localhost 使用。

优点

  • 跨平台（macOS/Linux/Win 一致）
  • 技术栈轻，性能好，UI 生态成熟（Vue/React）
  • 界面可以做得非常舒服：实时输出流、表格、状态徽章
  • 打包简单，一个命令启动

缺点

  • 不是"原生桌面窗口"（可套 Tauri 弥补）
  • 需要浏览器打开 localhost
B

Tauri 桌面应用

原生窗口 + 系统托盘，后端仍是本地服务调 gws。

优点

  • 真桌面应用体验：原生窗口、托盘、快捷键
  • 体积比 Electron 小很多（~10MB）

缺点

  • 构建链复杂（Rust 工具链），跨平台打包出包麻烦
  • 开发/维护成本最高，与"轻量"诉求相悖
C

TUI 终端界面

Go/Rust 写的终端 UI（如 lazygit 风格），键盘驱动。

优点

  • 最轻量，启动最快，装完即用
  • 不用离开终端

缺点

  • "界面友好舒服"天花板低，鼠标/拖拽支持弱
  • Windows 终端兼容性坑多
  • 与"可视化界面"的原始诉求不符
