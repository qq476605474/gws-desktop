# GWS Desk 使用说明书

> 面向使用者的完整使用手册（零基础可跟着做）。开发 / 维护相关请看 [`README-dev.md`](./README-dev.md)。

> 📌 **项目由来**：本项目由作者基于工作中实际遇到的痛点，借助 AI 辅助开发实现（并非作者手工逐行编写的传统程序），目的是解决实际工作问题、提高工作效率。欢迎使用，也欢迎提交 issue 反馈问题或建议。

## 这个软件是干什么的

GWS Desk 是 **gws** 的桌面客户端。

gws 解决的问题：你的项目由**多个 git 仓库**组成（比如 前端、后端、网关……），做一个需求时要在每个仓库各开一条分支。仓库一多，分支切来切去非常容易乱。

gws 的做法：

- 建一个 **hub（枢纽）目录**，把所有仓库「登记」进来统一管理；
- 每个需求 = 一个「**需求**」，它会**横跨你勾选的所有仓库**，在每个仓库里各建一条同名分支（git worktree），互相不干扰，**永远不用切分支**；
- 界面里的四个页签就对应四类东西：

| 页签 | 是什么 | 类比 |
|---|---|---|
| 需求 | 一次跨仓库的开发任务（一组分支） | 一张「需求卡片」 |
| 仓库 | 登记进 hub 的代码仓库 | 项目成员名单 |
| 环境 | 一批仓库在某个分支上的组合（如 dev / pre） | 联调环境 |
| 文档 | 每个需求配套的 Markdown 文档 | 需求说明书 |

> 代码的 commit（提交）目前仍在终端或 AI 助手里完成，客户端负责：看状态、拉取、推送、合并、收尾。

## 一、安装

### 第 1 步：安装 gws（必需）

GWS Desk 本身不含 gws，它只是遥控器，所以先装 gws。

**macOS / Linux**：打开终端执行

```bash
curl -fsSL https://raw.githubusercontent.com/qq476605474/gws/main/gws -o ~/.local/bin/gws && chmod +x ~/.local/bin/gws
```

装完确认一下：

```bash
gws version
```

- 如果提示 `command not found`，说明 `~/.local/bin` 不在 PATH 里：把下面一行加进 `~/.zshrc`（或 `~/.bash_profile`），然后重开终端：
  ```bash
  export PATH="$HOME/.local/bin:$PATH"
  ```

**Windows**：

- gws 是一个 **bash 脚本**，Windows 的 cmd / PowerShell 不能直接运行它，需要先装 **Git for Windows**（安装 Git 时会自带 Git Bash）：<https://git-scm.com/download/win>
- 装好后，**在「开始菜单 → Git → Git Bash」里**执行同样的命令：
  ```bash
  curl -fsSL https://raw.githubusercontent.com/qq476605474/gws/main/gws -o ~/.local/bin/gws && chmod +x ~/.local/bin/gws
  ```
- 这里的 `~` 在 Windows 上等于 `C:\你的用户名`，所以文件实际落在 `C:\你的用户名\.local\bin\gws`（Git Bash 里敲 `echo ~` 可以看到）。这个目录同样要加进 PATH：
  - Win+R 输入 `sysdm.cpl` → 高级 → 环境变量 → 用户变量里的 `Path` → 新建 `%USERPROFILE%\.local\bin` → 确定。
- 装好后 GWS Desk 会**自动借助 Git 自带的 bash 去执行这个脚本**，界面里所有按钮（同步、新建需求、推送……）都和 macOS 一样可用，不需要你做额外配置。若你用的是别的 gws（如 `gws.exe`、`gws.cmd`），客户端也会按 `gws.exe` → `gws.cmd` / `gws.bat` → `gws` 脚本的顺序自动识别。

### 第 2 步：安装 GWS Desk

| 平台 | 安装包 | 安装方式 |
|---|---|---|
| macOS（Apple Silicon，M 系列芯片） | `GwsDesk_0.1.0_aarch64.dmg` | 打开 dmg，把 GwsDesk 拖进「应用程序」 |
| Windows（Intel / AMD 64 位） | `GwsDesk_0.1.0_x64-setup.exe` | 双击，按向导下一步 |

两个包都**没有代码签名**，会有系统提示，属正常现象：

- **macOS**：首次打开提示「无法验证开发者」→ 在「系统设置 → 隐私与安全性」里点「仍要打开」；或右键 App 图标 → 打开。
- **Windows**：弹出 SmartScreen「未知发布者」→ 点「更多信息 → 仍要运行」。

## 二、第一次启动：打开或新建 Hub

启动页只做一件事：**确定你要管理哪个 hub**。

### 情况 A：已经有 hub（同事建的 / 命令行建的）

1. 在输入框填 hub 的目录路径，或点「**浏览…**」选择目录；
2. 点「**打开 Hub**」。
3. 成功：进入主界面，并且下次启动会**自动打开这个 hub**（想换就点顶栏「切换」）。
4. 报错「该目录不是 gws hub（缺少 .gws-hub 标记）」：说明选错目录了——hub 的根目录下一定有一个 `.gws-hub` 文件，找到它所在的目录再试。

### 情况 B：第一次用，还没有 hub

1. 点启动页下方的「**没有 hub？新建一个 →**」；
2. 填两项：
   - **父目录**：hub 要放在哪里（可点「浏览…」选，如 `~/Documents/dev`）；
   - **新目录名**：如 `myhub`；
3. 点「**创建**」。等价于命令行执行 `gws init ~/Documents/dev/myhub`，会生成标准目录结构（repos / envs / ws / docs），环境分支默认 `dev`；
4. 成功后**直接进入主界面**；失败会留在弹窗里，命令输出可见，改一改再试或点「取消」。

## 三、认识主界面

```
┌──────────────────────────────────────────────────────────────┐
│ GwsDesk   [需求] [仓库] [环境] [文档]        [切换][当前版本][设置] │  ← 顶栏
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                      当前页签的内容                            │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

- 四个页签：**需求**（默认）、**仓库**、**环境**、**文档**；
- 右侧「**切换**」：切换 / 新建 hub（悬停可看到当前 hub 路径）；
- 「**当前版本**」：查看 gws 版本、检查并更新 gws；
- 「**设置**」：主题与终端偏好。

几乎所有列表行右侧都有三个小按钮：

| 图标 | 作用 |
|---|---|
| 📋 | 复制该项的目录路径 |
| 📂 | 在访达 / 资源管理器中打开该目录 |
| 💻 | 在终端中打开该目录（用设置里选的终端） |

### 所有命令都在「命令弹窗」里执行

界面上每个动作（同步、新建、推送……）实际都是在跑一条 `gws` 命令。执行时会弹出一个黑底输出窗：

- 顶部显示命令名与状态：「执行中…」→「✓ 完成」或「✗ 失败」；
- 中间是实时输出（和终端里看到的一样），可以上滚查看；
- 「**终止**」：命令卡住或不想跑了，点它强制结束；
- 「**关闭**」：命令结束后必须手动点它关窗（防止误点丢失输出）。

有时命令自己会提问（比如删除时问「确认丢弃吗？」），会再叠一个「**gws 请求确认**」弹窗：点「**继续 (y)**」回答是，点「**取消（终止命令）**」回答否。

另外，危险操作（删除、推送、合并等）点按钮后会先弹「**确认操作**」框，点「确认」才真正执行——放心点错也不会立即生效。

## 四、从零开始的完整流程（跟做一遍）

假设团队有 `shop-api`（后端）、`shop-web`（前端）两个仓库，现在要做一个「收银台改版」需求。

### 1）添加仓库（仓库页签）

1. 打开「**仓库**」页签，点「**+ 添加仓库**」；
2. 「仓库地址」填 git 地址，可以一次填多个（空格或逗号分隔）：
   `git@github.com:team/shop-api.git git@github.com:team/shop-web.git`
3. 点「**添加**」，命令弹窗里能看到 clone 进度；
4. 成功后按提示点页签上的「**同步最新代码**」（即 `gws sync`），为每个仓库补建 worktree。
5. 仓库行上的灰色小字是「主干 <分支名>」，即这个仓库的主干分支。

> 「移除」按钮可以把仓库从 hub 除名（`gws repo rm`），会先弹确认。

### 2）新建需求（需求页签）

1. 打开「**需求**」页签，点「**+ 新建需求**」；
2. 填写：
   - **名称**（必填）：目录名，可中文，如 `收银台改版`；
   - **分支方式**二选一：
     - **前缀组合**（默认）：选前缀（`feature`、`bugfix`、`hotfix`、`release`、`support`、`docs`、`refactor`、`test`、`chore` 九选一），再填「分支名」英文后缀（如 `checkout-revamp`，留空就用名称）。最终分支自动拼成 `前缀-日期-后缀`，例如 `feature-20260831-checkout-revamp`，弹窗里有实时预览；
     - **完整分支名**：整支分支自己手填，原样使用；
   - **标题**（可选）：中文说明，默认同名称；
   - **基线来源**（可选）：从某个已有需求的分支拉出来（如 `需求A 阶段2`，可多个）；留空 = 从主干拉；
   - **模块（必选）**：勾选参与这个需求的仓库（本例勾 `shop-api` 和 `shop-web`）；
3. 点「**创建**」。命令弹窗执行 `gws new`，成功后需求列表出现新条目。

### 3）写代码 + 看状态（需求详情）

点列表里的需求名进入详情页。表格每行是一个模块（仓库），列含义：

| 列 | 含义 |
|---|---|
| 模块 | 仓库名 |
| 分支 | 该仓库里这个需求的分支 |
| 改动 | 未提交的文件改动情况 |
| vs远程 | `↑N ↓N`：本地领先/落后远程几个提交；「未推送」= 还没推过 |
| vs主干 | 领先主干几个提交（`+N`） |

在 📂 / 💻 打开的目录里正常写代码、用终端或 AI 提交（`git add` / `git commit`），然后回详情页点「**刷新**」即可看到最新状态。

详情页按钮一览：

| 按钮 | 作用 |
|---|---|
| Pull | 拉取远程更新到当前分支（有确认） |
| Pull --rebase | 以 rebase 方式拉取（本地未推送提交会被变基，有确认） |
| Push | 推送当前分支到远程；**有未提交改动时会被拒绝**，先提交再推 |
| Merge（本地） | 把当前需求合并进某个环境的**本地**分支，不推送，可先 review |
| Merge+Push | 合并进环境并**直接推送**远程（收尾用） |
| 同步最新代码 | 把主干（或指定来源）的最新提交合进当前需求分支 |
| Done 校验 | 检查是否所有模块都已并入环境，给出收尾前体检报告 |
| + 模块 | 给当前需求追加仓库（已包含的不再列出） |
| 删除需求 | 整个删除（文档自动归档；未推送的代码分支会保留），有确认 |

表格行内的「**移除**」：把某个模块从这个需求里退出（`gws drop`）；如果该模块还有未推送的提交，gws 会在命令弹窗里再问你一次是否丢弃。

### 4）合并收尾（两种姿势）

- **想先看看再推**：点「**Merge（本地）**」→ 弹窗里选环境（如 `dev`）→「开始合并」→ 再确认一次 → 完成。确认后去环境分支检查没问题，再手动推或走推送流程。
- **直接收工**：点「**Merge+Push**」→ 选环境 → 确认「确认把当前需求合并到 <环境> 并推送到远程？」→ 完成。
- 收尾前建议先点「**Done 校验**」，它会列出还没并入的模块。

> 如果弹窗里显示「（暂无环境，先在「环境」tab 创建）」，就先去环境页签建一个（见下节）。

### 5）环境（环境页签）

环境 = 多个仓库的同名分支组合，常用于联调（如 `dev`、`pre`）。

1. 「**+ 添加环境**」：填「环境分支名」（如 `pre`，合法 git 分支名即可，支持中文）。
   它会在各仓库检出**同名远程分支**为 worktree；**远程没有这个分支会报错、不会凭空创建**；
2. 点环境行可**展开**，查看该环境下各模块的状态；「（无模块，跑 gws sync 补建）」表示要先在仓库页签同步一次；
3. 「**同步最新代码**」：把环境下所有模块更新到环境分支最新；
4. 「移除」：删除环境（`gws env rm`），有确认。

### 6）文档（文档页签）

每个需求可以挂自己的文档，也可以有全 hub 共享的「根文档」。

1. 顶部下拉**筛选**：「根文档」或某个需求；
2. 「**+ 新建文档**」：填「文档名」（如 `技术方案.md`，**不能含空格**，回车也能提交）；「创建到」选择放在根文档还是某个需求目录（默认跟随当前筛选）；
3. 点文件名 → 用系统默认应用打开（装了 Typora / VS Code 就会用它们打开 .md）；
4. 「📋」复制文件完整路径（方便发给 AI：「帮我改一下这个文档」）。

> 文档的版本管理（commit 等）统一在命令行 / AI 里做，界面不提供文档提交入口。

### 7）导入别人的需求（需求页签 ⇄ 导入需求）

同事推送了一个需求分支，你想在本地接着做：

1. 点「**⇄ 导入需求**」（弹窗标题「拉取已推送的需求」）；
2. 「远程分支」：如 `feature-20260818-checkout-revamp`；
3. 「本地需求名」：留空会自动从分支名反推；本地已有同名时改个名；
4. 「标题」：可选中文说明；
5. 点「**拉取**」，成功后需求列表里就有了。

## 五、其他入口

### 切换 / 新建 hub（顶栏「切换」）

- 「目录路径」回显当前 hub，可改成别的路径（或「浏览…」选择）→「打开 Hub」；
- 切换后整个主界面重置（已打开的需求详情会关掉）；
- 弹窗下方的「**没有 hub？新建一个 →**」：和启动页一样，父目录 + 新目录名直接建新 hub，成功后自动切过去。

### 设置（顶栏「设置」）

- **外观主题**：浅色极简（默认）/ 深色开发者 / macOS 原生；
- **打开终端**：「💻」按钮用哪个终端（候选按你系统里装的终端自动生成；默认「跟随系统」）。

设置即时生效并自动保存。

### 当前版本 / 更新 gws（顶栏「当前版本」）

- 打开即自动检查：显示「当前版本」与「远端最新」，一致时标「● 已是最新版本」；
- 版本不一致会出现「**更新到 x.y.z**」按钮，点击执行 `gws update` 自动升级；
- 更新源：github.com/qq476605474/gws（可用环境变量 `GWS_UPDATE_URL` 覆盖）。

## 六、常见问题

**Q：启动页提示「未检测到 gws 命令」？**
按「安装」一节装好 gws；确认终端里 `gws version` 能跑通；mac 上若刚改过 `~/.zshrc` 的 PATH，**完全退出并重启 GWS Desk**（GUI 不继承终端的 PATH 修改）。

**Q：打开目录报「该目录不是 gws hub」？**
hub 根目录必须有 `.gws-hub` 标记文件（隐藏文件）。确认选中的是 hub 的**根**目录，而不是它下面的子目录。

**Q：命令弹窗一直「执行中…」不动？**
有些命令（同步、克隆）本来就慢；若怀疑卡住，看输出最后一行——出现「gws 已 N 秒无输出，可能正在等待输入。继续执行？」时点「继续 (y)」或「取消（终止命令）」；确实要中断就点「终止」。

**Q：Push 被拒绝了？**
有未提交的改动。先「💻」进终端提交（或让 AI 帮你提交），再回详情页点「刷新」→「Push」。

**Q：新建需求时「模块」一个都没得勾？**
还没添加仓库。先去「仓库」页签「+ 添加仓库」并「同步最新代码」。

**Q：合并弹窗里没有环境可选？**
先去「环境」页签「+ 添加环境」；注意环境分支必须**远程已存在**。

**Q：Windows 上提示「未检测到 gws」？**
依次检查：装了 Git for Windows 没有；在 Git Bash 里执行过安装命令没有（文件应在 `C:\你的用户名\.local\bin\gws`）；装完后是否重启过 GWS Desk（环境变量改动要重启才生效）。

**Q：Windows 上的提示「未知发布者」？**
程序未做代码签名，属正常；点「更多信息 → 仍要运行」。

## 七、已知限制

- **代码提交（commit）**：界面不提供，请使用终端或 AI 助手；
- **文档提交 / 上传 Confluence**：界面不提供，走命令行或 AI；
- **安装包未签名**：两平台首次打开都有系统安全提示（见安装一节）。
