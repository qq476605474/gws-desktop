# 发版流程

> 从改版本号到三端产物上线，一条线走完。下面所有命令都在仓库根目录执行。
> 个人/环境相关的注意事项在 `个人备忘.local.md`（该文件不入库）。

---

## 1. 升版本号：改三处

`crates/*/Cargo.toml` 里写的是 `version.workspace = true`，**不用动**。

| 文件 | 字段 |
|---|---|
| `Cargo.toml`（工作区根） | `version = "x.y.z"` |
| `src-tauri/tauri.conf.json` | `"version": "x.y.z"` |
| `package.json` | `"version": "x.y.z"` |

## 2. 本地编译（本机只能出 macOS 包）

```sh
npm ci                                   # 依赖被清过才需要
npm run tauri build -- --bundles app,dmg # → target/release/bundle/{macos,dmg}/
```

`beforeBuildCommand` 会自动跑 `npm run build`（vue-tsc + vite）和 `npm run bundle:cli`
—— 后者**自己会执行 `cargo build --release -p gws-cli`** 并把二进制拷进
`src-tauri/resources/`，所以**不需要**手工先编 CLI。

> 日常改代码只想跑测试时不用打包，见第 7 节。

## 3. 推送：这个仓库刻意只有**一个提交**

改动做完要发版时，把改动并进那唯一的提交，然后**重打 tag**：

```sh
git commit --amend --no-edit          # 改动并进唯一提交（不新增提交）
git tag -f -a vX.Y.Z -m "GWS X.Y.Z"   # ⚠️ amend 后必须重打，否则 tag 还指旧提交
git -c credential.helper='!gh auth git-credential' push -f origin main
```

推 tag（`git push origin vX.Y.Z`）在国内网络下经常超时；推不上去就改用 API：

```sh
# 新建（commit 必须已经在远端，否则 422）
gh api repos/qq476605474/gws-desktop/git/refs \
  -f ref=refs/tags/vX.Y.Z -f sha=$(git rev-parse HEAD)
# 已存在则移动
gh api -X PATCH repos/qq476605474/gws-desktop/git/refs/tags/vX.Y.Z \
  -f sha=$(git rev-parse HEAD) -f force=true
```

## 4. 触发三端构建

- **推 tag 会自动触发** `.github/workflows/release.yml`：三个平台各自构建
  （macOS dmg / Windows nsis / Linux deb + 三个 CLI），最后一个 job 汇总生成
  `sha256sums.txt` 并创建 Release。
- **用 API 建的 tag 不会触发 `push` 事件** → 手工触发，tag 由输入给出：

```sh
gh workflow run release.yml -R qq476605474/gws-desktop --ref main -f tag=vX.Y.Z
```

## 5. 产物命名（与 `update.rs` 逐字一致，否则「更新」会报找不到资产）

```
gws-desktop_<v>_aarch64.dmg        macOS 桌面端
gws-desktop_<v>_x64-setup.exe      Windows 桌面端
gws_<v>_amd64.deb                  Linux 桌面端
gws-aarch64-apple-darwin           macOS CLI
gws-x86_64-pc-windows-msvc.exe     Windows CLI
gws-x86_64-unknown-linux-gnu       Linux CLI
sha256sums.txt                     覆盖上面全部
```

对照 `crates/core/src/update.rs` 的 `desktop_asset_name()` / `asset_name()`。

⚠️ Tauri 的 `productName` 是 `GWS`，它产出的是 `GWS_<v>_<arch>.dmg` /
`GWS_<v>_x64-setup.exe`，**与上面不同名** —— 所以工作流里每个平台都有一步「重命名」，
别删。

## 6. 发布后核验

```sh
# 资产的 GitHub digest 与 sha256sums.txt 应逐条相等
gh release view vX.Y.Z -R qq476605474/gws-desktop --json assets \
  --jq '.assets[] | "\(.name)  \(.digest)"'
curl -sSL https://github.com/qq476605474/gws-desktop/releases/download/vX.Y.Z/sha256sums.txt

# 或者下载下来直接校验
gh release download vX.Y.Z -R qq476605474/gws-desktop -D /tmp/pkgs
cd /tmp/pkgs && shasum -a 256 -c sha256sums.txt
```

## 7. 本地验证（清过依赖后先 `npm ci`）

```sh
GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null cargo test --offline --workspace
cargo clippy --workspace --all-targets -- -D warnings
npm test && npm run check:vue
```

第一条里的两个环境变量是**刻意的**：模拟「机器上没有配 git 全局身份」的环境
（CI 的 Linux/Windows runner 就是这样）。测试夹具必须自己给 hub 配提交身份，
不能依赖机器 —— 否则只有在本机能过。

## 8. 想验证「更新」流程（把本机降到旧版本）

```sh
# 1) 临时降版本：Cargo.toml 与 src-tauri/tauri.conf.json 都改成 0.9.9
npm run tauri build -- --bundles app
cp -R target/release/bundle/macos/GWS.app /Applications/
# 2) 立刻还原，别把降版提交进去
git checkout -- Cargo.toml src-tauri/tauri.conf.json Cargo.lock
# 3) 打开 App → 设置 → 检查更新 → 应显示新版本 → 下载并更新
```

更新器会下载 `gws-desktop_<v>_aarch64.dmg`、对照 `sha256sums.txt` 校验、
原地替换 `/Applications/GWS.app` 然后退出重启。

## 9. 代码清干净以后怎么重新开始

发布用的构建产物（`target/` 约 8G）、依赖（`node_modules/`）、前端产物（`dist/`）、
Tauri 生成物（`src-tauri/gen/`）都可以随时删；恢复只需：

```sh
npm ci && npm run tauri build -- --bundles app,dmg
```

## 10. CI 是什么样

`.github/workflows/ci.yml` 是**三端矩阵**（ubuntu / macos / windows），每端都跑
`cargo test --workspace` + `clippy -D warnings`；另有前端 job 跑 `npm test` 与
`npm run check:vue`。几个跨平台坑（CRLF、`\\?\` 前缀、只在某平台编译到的死代码）
都是这个矩阵抓出来的，**别把它缩回单平台**。
